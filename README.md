# 墨图 · LEE Fiction Writing Editor

**让小说正文、章节规划与故事地图在同一个工作区自然连接。**

一款开源、自托管、前后端分离的小说编辑器。图形和箭头都可以关联章节，从故事地图直接跳转到正文。

[功能介绍](#功能) · [快速开始](#快速开始) · [部署](#部署) · [路线图](#路线图)

> [!NOTE]
> 项目目前处于 MVP 阶段，适合个人试用和自托管验证。多设备冲突合并、完整离线写作和多用户权限仍在开发路线中。

## 项目愿景

传统小说编辑器通常把正文放在一边，把大纲、人物关系和灵感便签放在另一边。墨图希望把它们变成可关联的数据：

- 一个故事节点可以链接到具体章节；
- 双击节点直接进入正文，不必反复翻目录；
- 节点便签记录写作目的、伏笔、冲突或待办；
- 调整故事结构不会破坏正文内容；
- 作者可以掌控自己的服务器和作品数据。

## 功能

- **Markdown 写作板**：宽幅连续写作界面、自动增高正文区、自动保存，以及粗体、标题、引用、列表、代码块等 Typora 风格快捷键。
- **快捷键浮窗**：按类型展示可用组合键，支持按名称、分类或按键搜索。
- **字体与排版**：可调正文字体、字号、行高、正文宽度、字色、字重、段间距与首行缩进，偏好保存在当前设备。
- **背景与稿纸**：提供薄雾灰、护眼绿、古典黄、静谧蓝、浪漫粉和云笺白六款写作背景，可切换无稿纸线、实线或虚线，并支持全局夜间模式；所有外观偏好只保存在当前设备。
- **查找与替换**：支持本章或全书搜索、上一处/下一处导航、大小写和全词匹配，以及当前、本章或全书替换；搜索窗可拖动、切换小窗或最小化，搜索高亮不会写入 Markdown 正文。
- **章节管理**：章节支持悬停单独删除，也可进入批量模式选择多个章节统一删除；删除前会显示影响范围并二次确认。
- **TXT 章节导入**：从作品目录旁的“导入/导出”入口打开，可批量 TXT 导入为自动编号的新章节，也可选择单个文件替换已有章节正文（标题及地图关联保留）；支持 UTF-8、GB18030/GBK 和 UTF-16 LE。TXT 换行与稿纸线对齐，空行用于分段。
- **TXT 全书导入**：可导入带“【章节】”、Markdown 标题或“第 N 章”等章节标记的整本 TXT，识别拆分后批量追加为新章节。
- **TXT 纯文本导出**：可从章节列表单选或多选章节；单选下载独立章节文件，多选可合并为一个文件或逐章分别下载；也可导出全书。组合导出按卷与章节顺序整理，使用 UTF-8 编码和 Windows 换行格式。
- **Markdown 导入导出**：可单章导出为 .md，多选可合并、逐章下载或打包 ZIP；支持批量导入 .md/.markdown 文件及 ZIP，可新建章节，也可将多个文件分别映射并替换现有章节正文，保留原章节标题和故事地图关联。
- **故事卷管理**：作品可以新增和删除故事卷，章节按卷分组；删除含章节的故事卷时会将章节移动到其他卷，正文和地图链接都会保留。
- **多故事地图**：一个作品可以新建、重命名、删除并切换多张故事地图；每张地图的节点、连线、便签、视野位置和章节链接彼此独立。
- **故事地图数据包**：可从地图列表选择单张或多张地图导出；单张生成 .leemap，多张打包为 ZIP（每张地图一个 .leemap）；导入时可新建地图或替换现有地图，节点样式与坐标、连线端点与样式、便签锁定状态和可匹配的章节关联都会保留。
- **流程故事地图**：提供长方形、圆角矩形、菱形、圆形、椭圆、平行四边形、六边形、文档和数据等图形。
- **端点与箭头**：普通图形使用四向端点，正六边形使用六角端点；箭头支持实线、虚线、点线、颜色、备注和章节链接。
- **双向章节导航**：箭头会标出链接章节，正文内可定位回对应图形或箭头，并返回故事地图。
- **区域操作**：在空白画布拖动框选多个图形，右键可直接删除图形、选区或箭头；整张画布可经二次确认后一键清空。
- **多便签系统**：普通便签悬停显示，锁定便签常驻，可随时编辑或删除。
- **章节直连**：从左侧目录选择章节建立链接，点击图形进入正文，也可随时断开。
- **扁平章节结构**：所有正文都作为独立章节管理，不再使用难以增删的二级场景；旧版场景会在升级时自动提升为章节并保留原文和地图链接。
- **按需扩展画布**：支持上下左右平移；画布仅在使用时有限扩展，大型流程图提供可拖动缩略图与一键回到初始中心。
- **前后端分离**：前端可连接任意自行部署的墨图后端。
- **跨平台 PWA**：支持手机与 Windows 浏览器，可安装到桌面。
- **自托管存储**：FastAPI + SQLite，提供可选 API Key 保护。
- **开放 API**：启动后可通过 `/docs` 查看交互式接口文档。

## 技术架构

```text
手机 / Windows / 浏览器（静态 PWA）
                 │
                 │ HTTPS + JSON API
                 ▼
          FastAPI 自托管服务
                 │
                 ▼
           SQLite 数据文件
```

核心数据被拆分为作品、章节、故事地图、节点和连线，而不是把思维导图保存成一张无法查询的图片。详细设计见 [架构说明](docs/architecture.md)。

| 模块 | 技术 | 说明 |
| --- | --- | --- |
| 前端 | HTML、CSS、JavaScript、PWA | 无构建依赖，可部署到任意静态托管 |
| 后端 | Python、FastAPI | 提供 REST API 与自动生成的 OpenAPI 文档 |
| 存储 | SQLite | 适合个人自托管，数据保存在单个文件中 |
| 部署 | Docker Compose | 一条命令启动后端服务 |

## 快速开始

本地开发推荐在项目根目录直接运行：

```powershell
python dev.py
```

它会同时启动前端和后端。浏览器访问 `http://localhost:4173`。

也可以按下面的方式分别启动两个服务。

### 环境要求

- Python 3.8 或更高版本
- 现代浏览器
- Docker（可选）

### 启动后端

```powershell
cd backend
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

### 启动前端

另开一个终端，在项目根目录执行：

```powershell
python -m http.server 5173 --directory frontend
```

浏览器访问 `http://localhost:5173`。默认后端地址为 `http://localhost:8000`，也可以在界面的“服务器设置”中改成远程服务器。

后端接口文档：`http://localhost:8000/docs`

## 部署

### 使用 Docker 部署后端

```powershell
docker compose up -d --build
```

作品数据默认写入名为 `lee-data` 的 Docker volume。

公网部署前建议配置 API Key 和明确的前端来源：

```powershell
$env:LEE_API_KEY="替换为足够长的随机字符串"
$env:LEE_CORS_ORIGINS="https://writer.example.com"
docker compose up -d --build
```

前端目录是纯静态文件，可以部署到 GitHub Pages、Cloudflare Pages、Nginx 或其他静态托管服务。公网环境中，前端与后端都应使用 HTTPS。

### 环境变量

| 名称 | 默认值 | 说明 |
| --- | --- | --- |
| `LEE_DATABASE_PATH` | `./data/lee.db` | SQLite 数据库位置 |
| `LEE_API_KEY` | 空 | 设置后要求 `Authorization: Bearer <key>` |
| `LEE_CORS_ORIGINS` | `*` | 允许访问 API 的前端来源，多个值用逗号分隔 |

## 当前限制

- 多台设备同时编辑时采用最后写入覆盖，尚未提供冲突合并界面。
- API Key 面向个人服务器，不等同于完整的多用户账户系统。
- Service Worker 当前缓存应用外壳，不缓存未同步的正文修改。
- SQLite 适合个人使用；多人实时协作需要进一步支持 PostgreSQL 和协作协议。
